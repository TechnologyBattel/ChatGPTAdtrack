# Tracking plan

Event names, field names and cookie behaviour verified against
`developers.openai.com/ads` (supported-events, measurement-pixel, conversions-api)
on **2026-10-24**. Re-verify before each release: the API has changed twice since May.

## Events

`event_id` is the dedupe key. Pixel and server copies of the same action must carry
the **same** `event_id`, the same **pixel id**, and the same **event name**.

| Event | OpenAI name | Fires from | Data type | Key properties | `event_id` rule |
|---|---|---|---|---|---|
| Page view | `page_viewed` | Browser | `contents` | `source_url`, session id | UUID v4 per view. Not sent per SPA route change. |
| Lead submitted | `lead_created` | Browser **and** Server | `customer_action` | `lead_id`, session id, `oppref` | One UUID generated by the lead form, reused by both paths. |
| Checkout started | `checkout_started` | Browser **and** Server | `contents` | `amount` (minor units), `currency` | Same UUID from the checkout component. |
| Order placed | `order_created` | Server only | `contents` | `order_id`, `amount`, `currency` | Derived from `order_id`, so a retry cannot double count. |
| Trial started *(optional)* | `trial_started` | Server | `plan_enrollment` | `plan_id`, `amount`, `currency` | `trial_<account_id>`. |
| Subscription created *(optional)* | `subscription_created` | Server | `plan_enrollment` | `plan_id`, `amount`, `currency` | `sub_<subscription_id>_<period>`. |
| Qualified lead *(optional)* | `custom` (via CAPI) or internal only | Server | `custom` | `lead_id` | `qual_<lead_id>`. Not a goal event. |

Server-only by platform rule: `app_installed`, `app_opened`. Custom events cannot be
optimisation goals, so `qualified` stays internal unless it is only for reporting.

## Field rules

- **Money**: integers in the currency's minor unit (₹899.00 → `89900`). `amount`
  always ships with `currency`. Never floats.
- **`oppref`**: event-level. Pass through **unmodified**; never invent or normalise.
- **`obref`**: lives under `user`. Read from the Pixel's `__obref` cookie and send
  unhashed. Never hash it.
- **PII**: only SHA-256 hashes (`emails_sha256`, `external_ids_sha256`), normalised
  first. Never raw email or phone.
- **`source_url`**: required for web events. Full URL with scheme and host.

## Cookies (Pixel-managed)

| Cookie | Lifetime | Notes |
|---|---|---|
| `__oppref` | 30 days | Rewritten (and expiry extended) on each new `oppref` in the URL |
| `__obref` | 365 days | Random browser reference; reused without extending expiry |

Neither may be read or written before consent. With consent denied, no cookie is set
and no event leaves the browser.

## Delivery path

```
browser ──▶ Measurement Pixel (public pixel id) ──▶ bzr.openai.com
   └──▶ POST /api/track (consent id required) ──▶ server ──▶ bzr.openai.com
                                                      same event_id
```

Guards on `/api/track` (all server-side, all tested):

| Guard | Failure |
|---|---|
| Server-issued consent id, HMAC-verified, unexpired, right scope | `403 consent_required` / `consent_invalid` / `consent_expired` |
| Origin allowlist (`TRACK_ORIGINS`) | `403 origin_not_allowed` |
| Per-IP rate limit (`RATE_LIMIT_PER_MINUTE`, default 60) | `429 rate_limited` |
| Body size (`MAX_BODY_BYTES`, default 256 KB) | `413 payload_too_large` |
| Event name in the supported set | `400 unsupported_event` |
| `amount` accompanied by `currency` | `400 missing_currency` |

## Dedupe

OpenAI deduplicates on **pixel_id + event name + event id** and keeps the **first**
event it receives. Therefore:

- Generate the id once, at the point of truth, and persist it with the lead/order.
- Retries must reuse the id; a retry with a new id is a second conversion.
- If the pixel fires and the server call later fails, do **not** mint a new id.

## Not yet implemented

- Pixel installation and the consent gate in the browser (`src/lib/api.ts` has the
  shape; no SDK is loaded).
- Persisting event ids with domain records (needed for retry safety).
- A delivery health view (`/health/events`) for deduped, failed and retried events.
