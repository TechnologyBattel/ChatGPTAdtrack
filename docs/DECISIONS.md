# Decision log

- 2026-09-30: Single organization (not multi-tenant) for v1.
- 2026-09-30: Firestore first; move to Postgres if analytics queries outgrow it.
- 2026-09-30: OpenAI CAPI key stored only in Cloud Function secrets.
- 2026-09-30: OpenAI-reported and internal attribution are always shown separately.
- 2026-09-30: One map with a metric switcher, not nine separate maps.
- 2026-10-24: "Keyword research" for ChatGPT Ads means **context-hint research**, not keyword bids. There is no keyword box, no negatives and no search-terms report, so we measure at ad-group level. See docs/PLAN.md §3.
- 2026-10-24: Hints are capped per set by quality (start 25–60), not by the API's ~2,000 limit; a 2,000-hint set is unlearnable.
- 2026-10-24: Internal attribution mirrors native defaults (30-day click, 1-day view-through) so the two numbers are comparable; both are always shown.
- 2026-10-24: India + INR are supported markets; the ₹725/day minimum campaign budget is accepted and must be reflected in budget modelling.
- 2026-10-24: All monetary values stored as integer minor units (paise/cents) + ISO-4217 currency; formatting happens only in the UI.
- 2026-10-24: The browser never holds an OpenAI key. The Ads API is called from a stateless server (`server/core.mjs`), deployed as a container; Vite proxies `/api` so there is no CORS and no localhost dependency.
- 2026-10-24: Live Advertiser data has no lead/customer/revenue columns. When first-party events are not configured, those values render as `—` instead of a confident ₹0.
- 2026-10-24: One segment per insights request. Country and device reports are kept in separate arrays so device rows never inflate totals.
- 2026-10-24: `/api/track` enforces consent, event id, event name and amount-currency server-side; the client is never trusted.
- 2026-10-24: Pushing a hint set returns the previous set, so every push is reversible.
- 2026-10-24: A hint push is two steps: an explicit diff (current vs proposed, with counts) then a confirm. No silent overwrites — the ad group's hints are replaced wholesale by the API, and OpenAI keeps no history.
- 2026-10-24: The rollback copy is the `previousHints` returned by our server, held in a local audit log. It survives reload, not a cleared browser profile; a server-side copy is a Slice 5 item.
- 2026-10-24: Failed pushes and failed undos are audited too. An audit trail that records only successes hides the incidents you need later.
- 2026-10-24: Auth is a server concern only. `AUTH_MODE=dev` uses a shared token and is refused under `NODE_ENV=production`; production must set `AUTH_MODE=firebase`. An unknown mode fails startup.
- 2026-10-24: Writes require `admin` or `owner`. `analyst` and `viewer` can read everything and change nothing. The check happens before any upstream call.
- 2026-10-24: A boolean is not consent. `/api/track` requires an HMAC-signed consent id (scoped, expiring) issued by `/api/consent`.
- 2026-10-24: `/api/health` is public but shallow (`{ok, mode}`). Key presence, account identity and upstream error text require a token.
- 2026-10-24: The one public write path (`/api/track`) carries the most guards: consent id, origin allowlist, per-IP rate limit, body cap. Rate limiting is in-memory and therefore per instance; a shared store is a production follow-up.
- 2026-10-24: Routing lives in `server/app.mjs` with no transport, so every rule is unit-testable without a socket.
- 2026-10-25: Consent ids are session-bound, single use and short lived (15 min; sessions 30 min). Verification is no longer stateless: the grant is persisted so a replay or cross-session use can be refused. Who can obtain an id, and why that is safe, is in docs/SECURITY.md §3.
- 2026-10-25: Signing keys are versioned (`CONSENT_SECRETS=v2:…,v1:…`). Rotation signs with the new key and still verifies the old one until those ids expire, so no visitor is asked twice for consent during a deploy.
- 2026-10-25: `AUTH_MODE=dev` refuses to start when any ad account key is set. Dev auth mints a write-capable token for anyone who can reach it; pairing that with a live account is an unauthenticated write path, so it is a startup error rather than a warning.
- 2026-10-25: `X-Forwarded-For` is believed only when `TRUST_PROXY` states how many of our own proxies are in front, and the client is read from the right. The header is attacker-controlled on the left, and the derived address is what the rate limiter keys on.
- 2026-10-25: The body cap is enforced while streaming, not from `Content-Length`, so a chunked body cannot bypass it.
- 2026-10-25: The auth token lives in `sessionStorage` with a memory fallback — never `localStorage`, and no cookies (no CSRF machinery means a cookie would be a net loss). The CSP forbids inline script in production; `index.html` ships none.
- 2026-10-25: `firebase-admin` is an `optionalDependency`, imported lazily only when `AUTH_MODE=firebase`. A missing module is a clear startup error, not a stack trace, and the demo/tests never load it.
- 2026-10-25: Sessions, consent records and push history sit behind one storage interface with memory and Firestore implementations. `consume` is compare-and-set inside a Firestore transaction, so concurrent replays cannot both win. `STORAGE=memory` is refused in production.
- 2026-10-25: Push history is server-side (`GET /api/audit`). The browser copy in `localStorage` is only a cache for the signed-out demo.
- 2026-10-25: Roles are set with `scripts/set-role.mjs`, never from the app. A role-editing route would let an admin promote themselves; the claim is written with service-account credentials and refresh tokens are revoked so a stale token cannot linger.
- 2026-10-25: The login screen is a full-screen overlay on the single page, not a route. Firebase sign-in goes over the public REST API instead of the ~150 KB Web SDK.
- 2026-10-25: The browser may not report leads, orders or amounts. `POST /api/track` accepts only low-value browser events (`page_viewed`, `contents_viewed`, `checkout_started`, `items_added`); money and identity go to `POST /api/events`, signed with a rotatable HMAC key over the raw body. A devtools user could otherwise claim a ₹99,999 order with a valid consent id.
- 2026-10-25: Consent is consumed only after the upstream accepts. An attempt *claims* the id (`pendingAt`), a retryable failure queues the event and keeps the claim, and a non-retryable failure releases it. The alternative — burn first, hope later — loses the visitor's consent on a upstream hiccup they never caused.
- 2026-10-25: Undelivered events go to an outbox in the store with exponential backoff and dead-lettering, not to a log line. After `OUTBOX_MAX_ATTEMPTS` the entry is dead, the consent id is released, and the give-up is audited. A dropped conversion should be a visible, queryable fact.
- 2026-10-25: Tracking sessions are bound to the user agent (hashed); an IP change is recorded but not enforced. Refusing on IP change breaks mobile commuters and shared NATs, and an IP is not a stable property of a person — so the binding is one we can honestly claim in SECURITY.md.
- 2026-10-25: Ad-group views read a separate `ad_group` insights report (`adGroupRows`); `adGroupId` is never back-filled from `campaignId`. Numbers rolled up from campaign rows are a different measurement, and a fabricated ad group would attach real spend to the wrong entity.
- 2026-10-25: The app is served same-origin as the API; there is no CORS. `vite.config.ts` proxies `/api` in dev and preview, production reverse-proxies it, and the CSP stays `connect-src 'self'`. CORS plus a widened `connect-src` is the only correct alternative, and both must move together or the browser blocks a call the server allowed.
- 2026-10-25: Firestore ships a deny-all `firestore.rules` and a hand-maintained `firestore.indexes.json`. The browser never touches the database (the Admin SDK bypasses rules), so denying everything cannot break the app, and an index file checked against the queries by a test cannot drift.
- 2026-10-25: With no first-party source connected, every first-party figure is masked — including the headline and subline, which are rewritten per intent rather than having numbers stripped by regex. "0 leads · ₹0 revenue" is a claim we cannot support, and broken prose is not an improvement on it.
- 2026-10-25: Research scores are the sum of their displayed parts, and the UI prints the arithmetic. A weighted score whose parts do not add up is a number nobody can audit, and the previous "researchable seeds = hints × 41" figure was invented.
- 2026-10-25: Multi-tenancy overrides the 2026-09-30 "single organization for v1" decision. The hierarchy is organization → workspace (one per client) → campaigns/topics/leads/sources. A separate `brand` level was rejected: `clientName` + `domains` on the workspace is enough for the MVP, and splitting a workspace later is a data migration rather than a schema change.
- 2026-10-25: The organization an operation touches comes from the caller's membership, never from the request body. A foreign id returns `404`, not `403`, and the body is identical to a nonexistent id, so the API cannot be used to enumerate tenants. A `workspaceId` in a body is ignored in favour of the route path.
- 2026-10-25: `memberships` and `ingestKeys` are stored globally (id `${orgId}__${userId}` and `${sourceConnectionId}.${keyVersion}`). Tenant-scoping them would make "which organizations am I in?" and "whose key is this?" unanswerable — the lookup itself is the question.
- 2026-10-25: Five organization roles (`viewer`, `analyst`, `editor`, `admin`, `owner`) and thirteen named permissions. Routes name a permission, never a role. Token roles are accepted broadly by `auth.mjs`; authorization always uses the membership role for the organization in the path.
- 2026-10-25: Qualification is allowed from exactly two paths: a member with `lead.qualify` (recorded with the actor) and a CRM source explicitly created with `trustedForQualification`. A browser or a marketing integration key can never qualify a lead, and an event cannot assert `qualification` or `revenue`.
- 2026-10-25: Lead-event identity is `sha256(workspaceId:eventId)` as the document id, inserted once. A replay returns `200 {duplicate:true}` rather than `409`: the sender's retry did succeed, and nothing was counted twice.
- 2026-10-25: A campaign registry entry carries `status: draft|ready|archived` **and** `launchState: 'not_launched'`. This phase does not launch ads, so the UI must never present a registry entry as serving traffic.
- 2026-10-25: The UTM builder returns every normalisation it applied (`normalized[]`). Rewriting a marketer's link silently would be a bug; showing the diff is the feature.
- 2026-10-25: Research topics record `origin: observed|suggested`, a source `{kind, reference, observedAt}` and a *computed* `freshness` (stale after 90 days, `unknown` without an observation date). Only an observed topic may be presented as evidence.
- 2026-10-25: No currency conversion anywhere. Money is integer minor units + ISO-4217, and a tripwire test fails if FX code appears. Retrofitting conversion would silently change every historical figure.
- 2026-10-25: Time zones are validated by IANA shape first, then resolved by `Intl`, because `Intl` accepts ambiguous abbreviations (`IST`, `EST`). Currencies are checked for membership in `Intl.supportedValuesOf('currency')`, because `Intl.NumberFormat` accepts any three letters.
- 2026-10-25: Local days are computed with `zonedDayRange` (a day can be 23, 24 or 25 hours), and out-of-range events are dropped from a bucket, never clamped to the edge. Clamping makes a partial day look complete — the same error class as a fake zero.
- 2026-10-25: Deleting a workspace revokes its ingest keys first, then purges its records. Ingest keys are global, so deleting only the source rows would leave a working credential pointing at a tenant that no longer exists. Found by a test written for the assumption, not by inspection.
- 2026-10-25: Retention is an application sweep (default every 6 h) with an owner-only manual purge that returns per-collection counts. The day counts (events 396, leads 760, audit 396, topics kept) are a policy choice, not a legal opinion.
- 2026-10-25: The Workspace panel is read-only. Writes are audited API actions that need their own confirmation flow; an un-audited button would be worse than the missing feature, and the gap is documented instead.
- 2026-10-25: No connector is built in this phase. `sources` provides credential lifecycle and capability rules, `docs/CONNECTORS.md` states the contract, and every provider that needs OAuth or paid credentials stays explicitly unbuilt rather than stubbed.
